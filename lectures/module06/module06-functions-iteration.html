Why write functions?

If you copy and paste the same code more than twice, write a function. - Dr. Deek (and basically everyone else)

  1. Automate repeated tasks more reliably than copying-and-pasting (i.e., avoid copy-paste mistakes).
  2. Named functions make your code easier to understand.
  3. Update code in one place instead of many.
  4. Reuse work across scripts and projects.

Three (main) kinds of functions

  • Vector functions: take one or more vectors as input and return a vector as output.
  • Data frame functions: take a data frame as input and return a data frame as output.
  • Plot functions: take a data frame as input and return a plot as output.

We will focus on the first two types of functions today.

  • There are other more advanced functions with varied input and output types.

What is a function?

  • In coding, like in math, a function takes input(s), performs a processes, and produces a result (output[s]).
    • \(3 = \sqrt{9}\) is a calculation.
    • \(y = \sqrt{x}\) is a function.
    • sum_var = x[1] + x[2] + x[3] is a calculation.
    • sum_var = sum(x) is a function.

For repeated tasks we would like to write a function with arbitrary inputs that produce corresponding outputs.

Writing a function: Identify a pattern

Let’s take a look at the repeated line out of the prior dplyr::mutate() statements:

(age - mean(age)) / sd(age)
(lwt - mean(lwt)) / sd(lwt)
(ptl - mean(ptl)) / sd(ptl)
(bwt - mean(bwt)) / sd(bwt)

Let’s put a placeholder where the variable changes.

(█ - mean(█)) / sd(█)

This will be our skeleton code for writing our z_score function.

The parts of a function

Every function consists of three parts:

  1. A name: e.g., z_score (it computes a z-score).
  2. The arguments: the thing that varies (e.g., x).
  3. The body: the code that is repeated across calls.
name = function(arguments) {
  body
}

Arguments

  • These are the inputs of your function.
  • They are used within the body of your function.
  • They can have default values.
name = function(df = data, na = FALSE) {
  body_do_something(df, na)
}
  • The names should be short but intuitive.
    • x, y, z for vectors.
    • df for data frames.
    • n for sample size, p for number of variables.

Body

  • What you want performed within your function.
  • A common flow is:
    • Input checks with warnings and/or error messages.
    • Perform operations.
    • Format output.

Return

  • What is output by your function.
  • Returns can be implicit using the last value produced (but not stored to an object).
name = function(df = data, na = FALSE) {
  body_do_something(df, na)
}
  • Or explicit with the return function.
name = function(df = data, na = FALSE) {
  out = body_do_something(df, na)
  return(out)
}
  • Returns can be single values (p-value) or a collection of values (test statistic and p-value), as well as named or unnamed.

Building z_score()

Remeber out template…

(█ - mean(█)) / sd(█)

Now let’s convert it into a proper function.

z_score = function(x) {
  z = (x - mean(x)) / sd(x)
  
  return(z)
}
  • Let’s try out the function on a few small examples before applying it to birthwt.
z_score(x = c(-10, 0, 10))

z_score(x = c(1, 2, 3, NA, 5))

Adjusting z_score()

There are two ways to adjust our function to handle NA values.

z_score = function(x) {
  (x - mean(x, na.rm = TRUE)) / sd(x, na.rm = TRUE)
}

z_score_na = function(x, na_logic = T) {
  (x - mean(x, na.rm = na_logic)) / sd(x, na.rm = na_logic)
}

Building another function

Our z_score function worked well with dplyr’s mutate.

  • z_score took an \(n \times 1\) vector as input and returned an \(n \times 1\) vector as output.

We will build a function that calculates the coefficient of variation: the ratio of the sample standard deviation to the sample mean.

  • Useful for comparing variability across variables measured on different scales.

\[cv = \frac{s}{\bar{x}}\]

  • Notice that by definition \(cv\) takes an \(n \times 1\) vector as input and returns a scalar (\(1 \times 1\)) as output.
    • Making it pair well with summarise().

Building cv()

cv = function(x, na.rm = FALSE) {
  sd(x, na.rm = na.rm) / mean(x, na.rm = na.rm)
}
  1. Name: cv.
  2. Arguments: x and na.rm = FALSE.
  3. Body: sd(x, na.rm = na.rm) / mean(x, na.rm = na.rm).

How about return? Implicit or explicit?

cv(x = birthwt$bwt)
[1] 0.2476457
cv(x = birthwt$age)
[1] 0.2280169
  • bwt and age are on totally different scales (grams vs. years).
    • cv() lets us compare their relative spread directly minimizes copying-and-pasting.

Data frame functions

  • So far we have focused on functions that take vectors as input and return vectors (or scalars) as output.
    • These pair well with some dplyr verbs.
  • But you’ll often also repeat the verbs themselves, particularly within a large pipeline or across analyses.
    • If you are copying-and-pasting multiple verbs multiple times, you may want to write a data frame function.
      • Data frame in, data frame (or vector) out.

A first attempt

  • First attempt throws error that “Column group_var is not found.”
  • Looking for variable named group_var i.e., not recognizing it as an argument input
  • In toy example want to use group and x but function uses group_var and mean_var variables

Let’s write a function that groups by one variable and averages another:

grouped_mean = function(df, group_var, mean_var) {
  df |>
    dplyr::group_by(group_var) |> # group by variable
    dplyr::summarise(mean = mean(mean_var), .groups = "drop") # calculate mean per group, drop groups
}

Embracing {{ }}

dplyr uses tidy evaluation, which allows you to refer to the names of variables without any special treatment ("" or $).

  • Tidy evaluation includes a solution to this problem called embracing {{ }}

Wrapping an argument in {{ }} tells dplyr to use the value stored inside the argument, not the argument as the literal variable name.

grouped_mean = function(df, group_var, mean_var) {
  df |>
    dplyr::group_by({{ group_var }}) |> # group by variable
    dplyr::summarise(mean = mean({{ mean_var }}), .groups = "drop") # calculate mean per group, drop groups
}

df_toy |> grouped_mean(group, x) # toy data, lazy eval
# A tibble: 1 × 2

  <dbl> <dbl>
1     1    10
birthwt |> grouped_mean(race, bwt) # birthwt date mean(bwt) by race, lazy eval
# A tibble: 3 × 2
  race   mean
  <fct> <dbl>
1 white 3103.
2 black 2720.
3 other 2805.

When to embrace?

  • Too many possible functions to enumerate, it is likely your first attempt at a function will have some errors.
  • Always check documentation

Check a function’s documentation for two terms:

  • Data-masking: functions that compute with variables.
    • E.g., arrange(), mutate(), filter(), summarise().
  • Tidy-selection: functions that select variables.
    • E.g., select(), relocate(), rename().

Functions and iteration

  • We use functions because they help us reduce duplication by minimizing copying-and-pasting code for a repeated task.
  • Iteration is another tool for reducing duplication when you need to do the same thing to multiple inputs.
    • Repeating the same operation on different columns, rows, or data frame.
      • Calculating the mean per column (variable).
      • Fitting a regression per dataset (data frame).

Two approaches to iteration

  • Imperative programming: Such as loops (for and while loops).
    • Make programming very explicit, so it is clear exactly what is happening. The downside is they can be verbose.
  • Functional programming (FP): Functions like base::lapply and purrr::map().
    • Functions that take other functions as inputs.
    • Can be abstract but solves common iteration problems with less code and fewer bugs.

For loops

purrr and map_*() functions

For loops make iteration explicit, but come with a repeated setup: allocate output, loop over the sequence, perform operation in the body.

  • The purrr package provides the map_*() family of functions, which reduce this overhead.
  • When provided with an input (vector, data frame, list, etc.) and a function, map_*() applies that function to each element of the input.
    • map() returns a list.
      • Equivalent to base::lapply().
    • map_dbl() returns a double vector.
    • map_chr() returns a character vector.
    • map_lgl() returns a logical vector.
    • map_int() returns an integer vector.

Things to remember

  • Functions and iteration automate repeated tasks more reliably than copying-and-pasting
  • Three major functions are vector, data frame, and plot functions.
  • A for loop has three parts: output, sequence, body and are explicit about each.
  • Functional programs handle some of the overhead associated with for loops.
    • across works on columns with dplyr verbs.
    • map_* and lapply are more flexible and can loop over columns, rows, files, or more.
      • lapply does not rely on other packges.
      • map_* is more flexible.
